1 · Connect

Pick where your agent runs. Every route reaches the same Shadow tools.

Codex, scripts and agents that run code, with their own key tested 20 and 21 Nov 2026

The agent signs in with its own Ed25519 key: no person, no account, no browser. Point it at the connect page and it has everything it needs:

https://mcp.clockchain.network/shadow/connect

The order to sign in, which the connect page is being updated to state:

  1. Record your steps. shadow_record returns each step's seq and hash.
  2. shadow_checkpoint, then sign its sign.hash and send it with shadow_sign_checkpoint. Before signing, sign.count should equal your last step's seq and sign.head its hash. The server's own opening steps are numbered with yours.
  3. shadow_close_session, then sign its sign.hash the same way. The close adds the server's closing steps, so its count is a few higher.
  4. Lost a hash? shadow_checkpoint returns the one still waiting, even after the close.

Codex sees that Shadow uses sign-in and opens the Clockchain page in your browser. Allow it (a new account shows its key once: save it). If the browser doesn't open, run codex mcp login shadow.

In the Codex app or terminal, Codex asks before each Shadow tool call. For unattended runs (codex exec), allow Shadow's tools first, or every call is refused:

codex exec -c 'mcp_servers.shadow.default_tools_approval_mode="approve"' "Record this task with Shadow: …"

To remove it: codex mcp logout shadow, then codex mcp remove shadow.

2 · Record

Logging is on by default once you're connected: the connector asks your agent to record its chat and tool steps as it goes. To be clear about it, name Shadow in the request:

Record this task with Shadow: <your task>. When you're done, close the session and give me the viewer link.

In our ChatGPT tests in November, the agent recorded the run every time Shadow was named in the request, and not when it wasn't.

Record only synthetic or redacted content. Anyone with the viewer link can read every step in full. Shadow filters some credential formats, not personal data.

3 · Close and share

Closing anchors a final checkpoint and returns:

You getWhat it isSend it
Viewer link…/shadow/s/<link>: the record as a web page, with its checksTo the person who checks
Packet link…/shadow/p/<link>.json: the same record as data, for toolsWhen they want the raw record
PinNames the key that signed. The trust check compares against it.Separately from the link

4 · Check it as a second person

Open the viewer link in your own browser, with no account. You'll see each step, its time window, and the verifier's result:

ResultMeans
passEvery check that applies passed: nothing was added, removed or changed since the steps were signed.
indeterminateNothing failed, but something couldn't be confirmed, often that every ledger receipt was reachable, or that every step has both time bounds. The viewer shows indeterminate until the session is closed, and for about a minute after, until the ledger receipts arrive.
failSomething doesn't match, for example a step changed after it was recorded. Don't rely on the record.

5 · Stop, revoke, delete

  • Say "stop logging" (clockchain_logging). It holds for the whole account. Turning the connector off also stops a chat.
  • Revoke a record's links with shadow_revoke_links.
  • Delete a record with shadow_delete_session, or the whole account. The ledger keeps only hashes, and they stay.

Tool reference

ToolDoes
shadow_start_sessionStarts a record and anchors a start marker
shadow_recordAdds one step: task, prompt, message, tool call, tool result, file or note
shadow_checkpointAnchors a checkpoint mid-session. With an agent key, returns the hash to sign.
shadow_sign_checkpointAgent keys only: sends your signature over a checkpoint
shadow_close_sessionFinal checkpoint, then the viewer link, packet link and pin
shadow_verifyRuns the verifier and returns each check
shadow_get_session, shadow_list_sessionsReads your records
shadow_revoke_links, shadow_delete_sessionStops the links working, or deletes a record
clockchain_loggingTurns logging off or on for the account

Limits

  • A pass shows the record is intact, not that the output is true, compliant or complete.
  • It covers what the agent recorded, not hidden reasoning or other apps.
  • Times are windows between ledger receipts.
  • Testnet only. Records are deleted 30 days after the session starts.
  • The ledger is our own single-operator gateway, and only hashes go on it.
  • No standalone verifier or public sample record yet.
